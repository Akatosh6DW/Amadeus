# QQ 配置与使用说明

适用于当前开发源码及后续发布包。当前源码的功能不能套用到旧版安装包；主 README 中的 v1.0.2 尚不包含这里的 QQ 功能。

## 第一次连接

1. 自行安装 QQ NT。Amadeus 只提供 NapCat 接入组件，不会下载 QQ 客户端；源码安装会下载固定版本组件，发布构建会内置该组件。
2. 打开 **设置 → QQ → 账号与登录 → 连接本机 QQ**。如果普通 QQ 正在运行，按提示自行退出后再连接；检测不到客户端时展开 **手动指定 QQ 路径**，选中 `QQ.exe`。
3. 在 **手机扫码登录** 区域使用手机 QQ 扫码并确认。二维码过期时刷新。启动组件、出现二维码都不代表登录成功。
4. 核对实际登录号。页面可能显示 **改用已登录账号 <QQ号>** 或 **连接这个账号**，按提示连接。地址和密钥由本机管理，无需反复填写；只有账号匹配、QQ 登录和连接均就绪，才算接通。
5. 在 **主人权限 → 你的本人 QQ 号** 填写自己的 QQ 号。助手专用账号与主人账号可以不同；账号用途选择 **Amadeus 的专用账号** 或 **我的个人账号（由 Amadeus 代回）**。
6. 在 **回复谁 → 添加好友或群** 选择对象，点击 **加入列表**。联系人尚未出现时点击 **刷新联系人**；也可手动填写号码。
7. 在 **回复设置** 选择发送方式，点击 **保存设置**。需要直接发送时选择 **自动回复，直接发送**；选择审核方式时只生成草稿，批准后才发。
8. 点击顶部 **▶** 开始回复。首次登录和切换账号都保持暂停，保存配置也不会替你开始接管。

NapCat 固定版本与校验值见 `configs/qq_component.json`，当前压缩包约 34.2 MiB，展开约 109.3 MiB。QQ 连接复用 Amadeus 的运行环境，不需要另装 AstrBot。

## 按钮分别做什么

| 操作 | 结果 |
| --- | --- |
| 顶部 ▶ / ⏸ | 开始 / 暂停自动回复；暂停保留连接和配置 |
| 对象旁 ▶ / ⏸ | 只开始 / 暂停这个好友或群 |
| 对象旁 **设置 ›** | 进入这个对象的独立设置页 |
| **保存设置** | 保存当前修改，不等于开始回复 |
| **刷新状态** | 重新查询连接和运行状态，不清空正在编辑的设置 |
| **切换配置账号** | 选择该 QQ 号保存的对象、偏好和上下文范围，保持暂停 |
| **重新登录 QQ** | 重新扫码登录；不替你切换已保存的账号配置 |
| **退出 QQ 后台** | 停止 QQ 连接与后台，保留已保存配置 |

默认随 Amadeus 退出 QQ 接管。只有在 **连接与后台** 开启 **退出 Amadeus 后继续后台运行**，才继续后台运行；之后可以回到这里点击 **退出 QQ 后台**。自动回复暂停时，已授权主人的远程控制入口仍可用于恢复；停止 QQ 后台或断开登录后，QQ 远程控制也不可用。

## 新增账号与一键切换配置

在 **账号与登录 → 新增 QQ 账号** 填写号码，再点击切换。已有配置可在 **已保存的 QQ 配置** 中选择后点击 **切换配置账号**。

- 新账号从空白、暂停的配置开始，不复制旧账号的回复对象、主人权限或聊天上下文。
- 已保存账号保留自己的对象、覆盖设置和偏好；切回后恢复，仍保持暂停。
- 切换会清理当前编辑器的未保存内容、联系人缓存，并取消旧账号尚未发送的任务。先保存想保留的修改。
- 配置选择与 QQ 实际登录分别核对。切换配置会检查实际登录号，不匹配时自动转入重新扫码；也可使用 **连接与后台 → 重新登录 QQ** 再次打开登录流程。核对实际登录号后再开始。
- 各账号的 QQ 对话按账号、好友/群、对象及身份/人格隔离。切换不会删除旧账号的历史，也不会把旧历史交给新账号。

新账号验收顺序：选择新号码 → 确认名单为空且暂停 → 扫码并核对实际账号 → 配置主人和一个测试对象 → 保存 → 点击 ▶。切回旧配置后，检查旧名单和设置仍在。真实发送必须另查平台回执，不能把“配置已保存”当成“已送达”。

## 每个对象单独设置

在 **回复谁** 中点击该对象旁的 **设置 ›**。留空或选择默认的选项继承全局设置；单独填写的选项只作用于这个对象。返回列表保留尚未保存的编辑，最后点击 **保存设置**。

- **对外说话方式**：以 Amadeus 本人的身份交流，或以主人的第一人称代回。它与账号用途、主人权限分别配置。
- **人格模式**：红莉栖、贴吧人格（孙吧）、最强攻击性语料（抗吧）。自动模式为私聊红莉栖、群聊贴吧；论坛模式使用独立的 QQ 回复上下文，不混入本地红莉栖人格。论坛语料是可选的本地文件，账号设置本身不包含语料文件；设置页会分别显示孙吧和抗吧索引是否已安装及记录数。
- **可选论坛语料**：需要时，把自己准备好的 `tieba.sqlite3` 或 `kangba.sqlite3` 放入 Amadeus 用户资料目录的 `persona` 文件夹，重新打开或刷新 QQ 设置即可读取。页面显示“未安装语料”时，论坛模式仍可保存和使用，但不会有该索引提供的语料示例；程序不会自动下载、删除或替换本地语料。
- **回复如何发送**：自动发送或生成待批准草稿。
- **回复形式、气泡字数、回复排版**：短句可拆成多条消息；可以选择单行、不在句末加句号。语音保留完整音频，不按文字气泡拆开。
- **语音比例、语音语言**：必须由主人开启语音模式。0% 只发文字，100% 每条语音，中间值按概率选择；中文/日文可与本地桌面朗读分开。普通聊天对象不能替主人改变语音模式，已授权主人可以通过对话修改。
- **等待方式、最短间隔**：固定等待或按字数等待。按字数模式在基础等待上增加约字数 ÷ 6 秒并有小幅浮动，最长 30 秒，生成回答的耗时另计。最短间隔限制连续发送频率；每小时发送上限可在设置中调整。
- **历史条数、回复要求**：自动读取近期消息，区分发送者和引用对象；需要更早内容时可继续调用历史工具。群历史条数设为 0 时，触发后仍读取最近 10 条。当前明确的回复要求优先于这个对象的记忆和旧聊天内容。

**清理上下文** 只清理该对象在 Amadeus 中的会话上下文，不删除 QQ 平台聊天记录，也不删除账号配置。它不是增加模型上下文容量的替代品。

## 群聊什么时候回复

在群的二级设置页配置 **什么时候参与这个群的聊天**：

- **有人 @ 我**：QQ 的实际 @ 目标是当前登录账号，即使 @ 后面没文字，也会读取上下文再决定回复。
- **消息包含关键词**：命中配置的关键词时触发。
- **有人引用回复我的消息**：引用当前助手账号发出的 QQ 消息时触发。
- **任何新消息**：群内新消息都可触发；与上述三个条件互斥。

前三项可以组合。后台接收 QQ 事件并判断触发条件，只有匹配且没有暂停等限制时才请求模型生成回复；并非每条群消息都让模型完整思考一次。引用、表情包和图片会尝试补取原消息和图片；平台没有提供可读资源、图片过期或视觉模型不可用时，不能凭占位符知道图里是什么。

## 主人通过 QQ 操控

在 **主人权限** 中填写本人的 QQ 号，开启 **允许主人通过 QQ 操控助手**。需要群内控制时，再开启群控；群必须在允许范围内，消息要实际 @ 当前助手账号。判断主人使用真实 QQ ID，不凭昵称或自称。

主人可以用自然语言修改回复对象、暂停/恢复、语音/文字、语言、人格，或调用本地已允许的工具。修改写入同一套配置，设置页刷新后能看到；QQ 普通聊天对象没有这些控制权限。群内正常聊天和可公开结果照常回群；本地文件、私人历史、配置等敏感结果走主人私聊。

开发者模式另外提供确定性的 `/dev pause`、`/dev resume` 及加 `all` 的暂停/恢复指令。它仍核对实际主人、登录账号和允许的群，不会让任意群成员取得本地权限。

设置、对象名单和语音偏好保存在工程配置中，不应写成主人的长期个人记忆。人的事实与关系使用独立认知库，优先级低于主人当前明确要求。主聊天不会自动装入每个 QQ 对话的完整历史；按任务读取对应对象的上下文。

## 图片、表情包、语音与 QQ 空间

- 在主对话上传图片后，可以要求转发给已配置的 QQ 对象。当前附件可以临时发送；需要反复选用时，导入 **QQ 图库**。
- 图库支持 PNG、JPEG、WEBP、GIF，单文件上限 10 MiB。发送成功要有平台回执；嘴上说要发图不算发出。
- QQ 语音复用桌面的合成管线，语言和发送比例单独配置。先完成本地语音环境和音色设置。
- QQ 空间有独立开关、读写权限、发布设置和自主运行间隔。允许 QQ 聊天不等于开启空间发布；当前空间发布为文字。登录态失效时需重新登录，不能把生成了动态草稿当作已发布。

## 常见状态与排错

| 看到的状态 | 先检查什么 |
| --- | --- |
| 组件运行，但 QQ 未连接 | 手机是否确认登录、实际账号是否匹配、QQ 核心和 OneBot 是否就绪；刷新状态后按页面的账号连接提示操作 |
| 登录号与配置号不同 | 切到该登录号的配置，或重新登录目标 QQ；不要带着旧账号名单强行开始 |
| 能看到消息但不自动回 | 顶部和单对象是否暂停、对象是否加入列表、群触发条件、最短间隔和发送上限 |
| 总让我确认才发 | 当前对象或全局是否选择了“先生成草稿，我确认后才发送” |
| 表情包只显示占位符 | 原消息/图片是否还可获取、视觉模型是否支持图片；不能用占位符证明识图成功 |
| 提醒到点没送达 | 后端和 QQ 是否持续运行、任务是否包含 QQ 发送动作、活动记录是否有实际平台回执 |
| 发送结果未知 | 查 QQ 实际聊天及活动回执，不自动重复发送，避免对方收到多次 |
| 切换后看不到旧联系人 | 先核对当前配置号；不同账号隔离，切回旧配置才恢复其名单 |

QQ 发送成功默认不再给主聊天额外刷成功汇报，失败或结果未知会提示；详细动作可查看 QQ 活动。搜索、文件等工具仍遵循你设置的权限。程序不再要求按固定措辞重复授权普通调用，也不会把风格或称呼当成发送许可。

开发者验证时应使用隔离运行目录和模拟网关。真实前端、真实模型、模拟 QQ 回执、真实 QQ 送达是不同的证据，必须分开记录；仅跑单元测试不能认定真实扫码或送达通过。
